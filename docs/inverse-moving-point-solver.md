# Inverse moving-point coordinate solver

\n\n## Purpose\n\nThe 2025 Shizuoka exam example selects a moving point P on the arc from D to C not containing A, under the condition BA = BG, where G is the intersection of AP and BD. This module reverses the earlier experiment: it calculates G and P from a supplied fixed coordinate layout, then checks whether the calculated P is on the required arc.\n\n## Calculation\n\n1. Calculate BA and BD. If BA > BD, no point G on segment BD can satisfy BG = BA.\n2. Move from B toward D by distance BA to calculate G.\n3. Write points on line AG as A + t(G - A). Since A is already on circle O, the other circle intersection has\n\n   `t = -2 ((A - O) · (G - A)) / |G - A|²`.\n\n4. Require the second intersection to occur after G in the A-to-G ray order, and calculate P.\n5. Check that P lies strictly inside the D-to-C arc that does not contain A, and is not one of the excluded points.\n\n## Limits\n\n- This implementation intentionally supports only the encoded A/B/D/O and arc pattern in the example data. It is not a general geometry solver.\n- The caller supplies coordinates for the fixed points; this module does not infer a layout from the diagram.\n- A successful result shows that one supplied layout admits a numerical solution. It does not prove that every allowed layout has a solution, validate every source constraint, or prove the similarity theorem.\n- The checker and this solver remain separate; callers can pass the returned P and G to the coordinate-witness checker to test the supported constraints.\n
