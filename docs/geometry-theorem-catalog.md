# 中学図形証明の定理・性質カタログ（初版）

> 状態: 初版・レビュー前  
> 目的: 証明問題メーカーで使う推論ルールの仕様を、実装より先に明文化する。  
> 範囲: 2017〜2026年の問題分析表に記録された性質と、現在の `js/proof-rules.js` にあるルール。  
> 注意: これは「中学数学で使う全定理を網羅した完成版」ではない。まず出題分析・既存実装から確認できるものを整理し、教科書範囲と過去問本文・図を照合して拡張する。

## 1. このカタログの原則

各ルールは少なくとも次の項目を持つ。

- **一意なID**: コード・テスト・証明ログで共通に使う。
- **前提条件**: その定理を適用するために明示的に必要な条件。
- **結論**: 前提から新しく導いてよい事実。
- **証明理由**: 生徒に見せる日本語の理由。
- **出典・範囲**: 過去問分析表、教科書範囲、または追加調査のどれに基づくか。
- **正例テスト**: 前提がそろったときに結論を導ける。
- **負例テスト**: 前提が不足・不一致のときに結論を導けない。

**図の見た目だけから事実を推測しない。** 例えば、2直線が図上で平行に見えることは `parallel(l,m)` の根拠にしない。平行であることは問題の条件か、証明済みの結論でなければならない。

また、図形の定義・点の位置・直線の交点・弧の選択などの条件は、単なる文字列一致だけで済ませず、構造化して検査する設計を目指す。記号例は初期案であり、最終的な内部データ形式は別途決める。

## 3. ルール仕様の初期カタログ

### A. 角の基本関係

#### A1. 対頂角は等しい
- ID: `angle.vertical-angles`
- 前提: 2本の直線が交わり、対象の2角が対頂角である。
- 結論: 2角の大きさが等しい。
- 重要な制約: 頂点が同じだけでは足りない。交差する2直線と角の位置関係が必要。
- 負例: 隣り合う角を対頂角として扱わない。

#### A2. 平行線の錯角は等しい
- ID: `parallel.alternate-interior-angles`
- 前提: 2直線が平行で、横切る直線がそれぞれと交わり、指定した角が錯角の位置にある。
- 結論: その2角が等しい。
- 負例: 平行条件がない場合、または指定角が錯角の位置にない場合は導かない。

#### A3. 平行線の同位角は等しい
- ID: `parallel.corresponding-angles`
- 前提: A2と同様に平行条件と横切る直線があり、指定角が同位角の位置にある。
- 結論: その2角が等しい。
- 負例: 位置関係の異なる角を同位角として扱わない。

#### A4. 三角形の内角の和
- ID: `triangle.angle-sum`
- 前提: 対象が三角形である。
- 結論: その三角形の3内角の和は180°。
- 負例: 三角形の内角でない角を含めない。

#### A5. 三角形の外角定理
- ID: `triangle.exterior-angle`
- 前提: 三角形の1辺を延長してできる外角と、残り2つの内角が正しく指定されている。
- 結論: 外角は、隣り合わない2つの内角の和に等しい。
- 負例: 隣接する内角や別の三角形の角を代入しない。

#### A6. 角の加法・減法
- ID: `angle.addition`
- 前提: 1つの角が、内部の半直線で重なりなく隣り合う複数の角に分割されていることが分かる。
- 結論: 全体の角度は部分角の和。必要に応じて、等式から部分角を比較できる。
- 負例: 角の内部にない半直線や、重なりのある角を勝手に足さない。
- 注意: 角の加法は「角の名前が似ている」だけでは適用できない。点の並びと半直線の関係が必要。

### B. 二等辺三角形

#### B1. 2辺が等しい三角形の底角は等しい
- ID: `triangle.isosceles-base-angles`
- 前提: `triangle(A,B,C)` と `side(AB)=side(AC)` のように、三角形と等しい2辺が明示されている。
- 結論: その2辺に対する底角が等しい（例: `angle(ABC)=angle(BCA)`）。
- 負例: 等しい辺が対象三角形に属さない場合は適用しない。

#### B2. 2角が等しい三角形の対辺は等しい
- ID: `triangle.equal-angles-imply-equal-sides`
- 前提: 対象三角形の2内角が等しい。
- 結論: それらの角の対辺が等しい。
- 負例: 三角形の内角でない角の等しさだけでは適用しない。

### C. 円

#### C1. 同じ弧に対する円周角は等しい
- ID: `circle.inscribed-angles-same-arc`
- 前提: 2つの角が同じ円周上の同じ弧（または同じ弦を見込む、条件が整合する弧）に対する円周角である。
- 結論: 2つの円周角が等しい。
- 負例: 弧・円・角の対応が異なる場合は適用しない。
- 注意: 弧を端点の文字列だけで比較すると、大小の弧や点の位置を取り違えるおそれがある。円と弧を構造化する必要がある。

#### C2. 等しい弧に対する円周角は等しい
- ID: `circle.equal-arcs-inscribed-angles`
- 前提: 同一円（または同じ条件で比較可能な円）上の等しい弧に対する円周角である。
- 結論: その円周角が等しい。
- 負例: 等しい弧の条件がない場合や、角と弧の対応が合わない場合は適用しない。

#### C3. 同じ弧に対する中心角は円周角の2倍
- ID: `circle.central-inscribed-angle`
- 前提: 中心角と円周角が同じ円・同じ弧に対応している。
- 結論: 中心角 = 2 × 円周角。
- 負例: 対応する弧が違う場合や、中心が当該円の中心と確認できない場合は適用しない。

#### C4. 直径に対する円周角は90°
- ID: `circle.diameter-inscribed-angle`
- 前提: 角の頂点が円周上にあり、角の両端点が直径の両端である。
- 結論: その円周角は90°。
- 負例: 直径の端点・円周上の頂点のいずれかが確認できない場合は適用しない。

#### C5. 同じ円の半径は等しい
- ID: `circle.equal-radii`
- 前提: 2本の線分が同じ円の中心から円周上の点へ引かれた半径である。
- 結論: その2線分の長さは等しい。
- 負例: 円の中心が異なる、または端点が円周上にあると確認できない場合は適用しない。

### D. 三角形の合同・相似

#### D1. 相似条件（2組の角）
- ID: `triangle.similarity-aa`
- 前提: 2つの三角形と、対応関係が明確な2組の角の等しさがある。
- 結論: 2つの三角形は相似。
- 負例: 角の対応が食い違う、または異なる三角形の角を混ぜている場合は適用しない。
- 注意: `similar(ABC,DEF)` の文字順は頂点の対応 A↔D、B↔E、C↔F を意味する。結論と対応角の順序をテストで検査する。

#### D2. 合同条件（3組の辺）
- ID: `triangle.congruence-sss`
- 前提: 2つの三角形の3組の対応する辺がそれぞれ等しい。
- 結論: 2つの三角形は合同。

#### D3. 合同条件（2組の辺とその間の角）
- ID: `triangle.congruence-sas`
- 前提: 2組の辺がそれぞれ等しく、その2辺にはさまれた角も対応して等しい。
- 結論: 2つの三角形は合同。
- 負例: 「2辺と、その間ではない角」だけではこの条件を適用しない。

#### D4. 合同条件（1組の辺とその両端の角）
- ID: `triangle.congruence-asa`
- 前提: 1組の対応する辺が等しく、その辺の両端の2角がそれぞれ等しい。
- 結論: 2つの三角形は合同。

#### D5. 合同な三角形の対応する辺・角
- ID: `triangle.congruent-corresponding-parts`
- 前提: 合同が証明済みで、頂点の対応順序が明確。
- 結論: 対応する辺の長さと角の大きさがそれぞれ等しい。
- 負例: 頂点の順序を入れ替えた誤った対応を出さない。

### E. 線分と等式の推論

#### E1. 線分の加法
- ID: `segment.addition`
- 前提: 点が同一直線上にあり、指定した点が線分の間にあることが確認できる。
- 結論: 全体の長さ = 部分の長さの和。
- 負例: 点の順序が分からない場合や、点が線分上にない場合は適用しない。

#### E2. 等式の推移
- ID: `logic.equality-transitivity`
- 前提: 同じ種類・同じ意味の量について、A=B と B=C が証明済み。
- 結論: A=C。
- 負例: 長さと角度など、異なる種類の量をつながない。
- 注意: 左右の向きが逆の等式も正規化して扱う。単なる文字列の左右一致だけに依存しない。

## 4. 定理カタログと証明エンジンの接続状況

`js/theorem-catalog.js` を `js/proof-rules.js` より先に読み込むようにし、証明エンジンから `TheoremCatalog.get(id)` で正式な定理データを参照できるようにした。

- `derive` と `prove` が返す証明ステップは、IDがカタログに登録されていれば、定理名と説明文をカタログの値で統一する。
- `catalogStatus(ids)` で、指定したIDがカタログに存在するかを検査できる。
- 統合テストで、現在の実行時ルールが出す正規IDがカタログに登録されていることを確認する。
- カタログが読み込まれていない環境向けの互換フォールバックは残しているため、カタログが必須であることを全環境で強制する段階には至っていない。

これは定理IDと表示メタデータを一本化する接続であり、カタログ内の型付き前提・結論を汎用マッチャーで実行する処理まで完成した、という意味ではない。証明エンジンには引き続き個別の文字列ベース規則があり、型付きカタログの全項目から推論する仕組みは今後の作業である。

## 5. 現行実装との関係

現行の `js/proof-rules.js` は、二等辺三角形の底角、錯角、直径の円周角、相似AA、合同SSS/SAS/ASA、合同図形の対応、角の表記、円周角・中心角の一部、等式の推移を扱っている。

ただし、ルールが存在することは、幾何条件の検証まで完成していることを意味しない。現在の実装には文字列としての事実照合が多く、例えば円の同一性・弧の位置・三角形の頂点対応・角の分割関係を厳密に確認できない箇所がある。このカタログは、その不足を今後のテストとデータモデルで明らかにするための基準とする。

## 6. 実装・テストの優先順位

1. **定理データの形式を統一する**: ID、前提パターン、結論パターン、理由文、必要な幾何構造。
2. **既知の事実と推論事実を区別する**: 各事実に出典（問題の仮定／どのルールから導いたか）を保持する。
3. **ルールごとの正例・負例を作る**: 前提が1つ欠ける、点の順序が違う、対応角が違う等を必ず試す。
4. **記号の文字列処理を構造化する**: 角、線分、三角形、円、弧、直線、点の位置関係を型付きデータにする。
5. **このカタログを基準に既存コードを評価する**: 仕様に合わない部分は段階的に置き換える。先に全部を削除しない。
6. **過去問の証明を手作業で再確認する**: 分析表の記述を原問題の条件・図と照らし合わせ、ルールの適用が妥当か確認する。

## 7. 未整理・追加調査が必要な候補

これは現時点で実装済み・過去問で使用確認済みと断定するリストではなく、中学図形の証明エンジンとして必要性を検討する候補。

- 三角形の合同条件・相似条件の完全な対応関係
- 平行線になることを示す逆の定理（錯角・同位角などの逆）
- 角の二等分線に関する性質
- 円周角の定理の逆や、同じ弦・弧に対する角の扱いの整理
- 弧・弦・中心角の関係
- 直角三角形の合同条件
- 中点・垂直二等分線・垂線に関する性質
- ひし形・平行四辺形など四角形の性質（対象学年・問題範囲を確認して採否を決める）
- 比例式・相似比と辺の比
- 点の順序・交点・延長線を含む配置条件の表現

候補を追加する際は、教科書範囲と対象年度の問題に必要かを確認してから正式なルールに昇格させる。


## 8. 機械可読データの初期実装

`js/theorem-catalog.js` に、型付きの前提・結論を持つルールデータを作り始めた。最初の対象は、二等辺三角形、対頂角、三角形の内角の和、平行線の錯角・同位角、外角定理、角と線分の加法、円の基本性質、相似AA、合同SSS/SAS/ASA、等式の推移など。

データ例の考え方:

- `{ type: "triangle", vertices: ["A", "B", "C"] }`: 三角形ABCであるという事実
- `{ type: "equal-segments", segments: [["A", "B"], ["A", "C"]] }`: ABとACの長さが等しいという事実
- `{ type: "equal-angles", angles: [["A", "B", "C"], ["B", "C", "A"]] }`: 指定した2角が等しいという事実
- `{ type: "diameter", circle: "O", endpoints: ["B", "C"] }`: 円Oの直径BCという事実

**重要:** この段階では、ルールの仕様を型付きデータとして記述したところまでであり、全ルールを実際に適用する汎用マッチャーや幾何配置の検証器はまだ完成していない。また、`tests/theorem-catalog.test.js` はカタログの構造を検査するテストで、各定理の数学的妥当性を実証するテストではない。そこを混同せず、次はこのデータ形式に対する推論処理と定理ごとの正例・負例テストを実装する。


## 最初の実装：三角形の内角の和

`js/proof-rules.js` に、カタログの「三角形の内角の和」を推論できるルールとして追加した。

- 入力事実の形式：`triangle(ABC)`（三角形の3頂点を明示する）
- 導く事実の形式：`angle(BAC)+angle(ABC)+angle(ACB)=180`
- 頂点名が異なる三角形にも同じ規則を適用する。
- 三角形の事実がなければ導かない。同じ頂点を重ねた `triangle(AAA)` も拒否する。
- `derive` と `prove` の両方で利用でき、証明ステップには使用した前提と定理名を記録する。

これは文字列で表した事実を使う既存の証明エンジンへの小さな追加であり、図から三角形を自動認識する処理や、角度の数値計算を実装したものではない。


## 追加実装：同じ円の半径は等しい

`js/proof-rules.js` に、同じ中心をもつ円の半径の等しさを導く規則 `circle.equal-radii` を追加した。

- 入力事実の形式：`onCircle(A,O)` と `onCircle(B,O)`（A、Bが中心Oの同じ円周上にある）
- 導く事実の形式：`side(OA)=side(OB)`
- 円の中心が異なる場合や、円周上の点が1つしかない場合は結論を導かない。
- `derive` と `prove` の両方で利用でき、証明ステップに2つの前提を記録する。

この文字列形式は実装中の証明エンジンに合わせたもの。定理カタログ側の型付きデータとの完全な変換・統合は、今後の作業として残している。


## 追加実装：対頂角は等しい

`js/proof-rules.js` に、対頂角として明示された2つの角が等しいことを導く規則 `angle.vertical-angles` を追加した。

- 入力事実の形式：`verticalAngles(ABC,DBE)`（∠ABC と ∠DBE が対頂角であることを明示）
- 導く事実の形式：`angle(ABC)=angle(DBE)`
- 頂点が同じというだけでは対頂角と判断しない。交わる2直線と角の位置関係を事実として与える必要がある。
- 正例、隣の角を誤って等しいとする負例、頂点が一致しない不正な入力の負例を追加した。

現段階では、図から交差する直線や対頂角を自動認識する機能は含まない。
