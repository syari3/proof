# 定理カタログ実装状況の監査

> 対象ブランチ: `theorem-catalog-foundation`  
> 監査日: 2026-10-10  
> 対象: `js/theorem-catalog.js` の一意な定理ID 19件と、`js/proof-rules.js` / `tests/proof-rules.test.js`  
> 注意: 「実装あり」は数学的な条件検証まで完成した意味ではない。文字列ベースの既存ルールや、目標に合わせてのみ働く推論も含む。

## 集計

- **カタログの型付き定義**: 19/19件（100%）。ただし、これは初版19件のデータがある割合であり、中学図形の必要定理全体に対する登録率ではない。必要な定理の総数はまだ確定していない。
- **実行エンジンに何らかの対応あり**: 17/19件（約89.5%）。このうち多くは固定された記号パターンや文字列照合に依存する部分実装。
- **汎用的な推論処理を追加し、個別テストもあるもの**: 4/19件（約21.1%）を暫定的に数える。三角形の内角の和、同じ円の半径、明示された対頂角、三角形の外角定理。対頂角は「図から対頂角を見つける」機能までは含まない。
- **実行テストで確認できた対応**: 少なくとも15件に関連するテストはあるが、カタログIDと既存エンジンのIDが一致していない箇所があるため、19件すべてをカタログID単位で正例・負例検証済みとは扱わない。
- **カタログの正例・負例テスト説明欄**: 19/19件（100%）。これはテストの説明文が登録されている割合で、実際のテスト実行率ではない。

## 件数の数え方に関する訂正

説明文には一般的な項目名として `circle.inscribed-angle` があり、実データでは具体化した `circle.inscribed-angles-same-arc` を使っている。これは別々のIDではないため、実データの一意な定理IDは19件。過去の説明で「19件」と「カタログに列挙した項目数」が混ざっていたので、今後は実データの一意なIDを分母として数える。

## 次に進める順序

1. カタログIDと実行ルールIDの対応表を作り、テストをID単位で結びつける。
2. 同位角、外角定理、角の加法、線分の加法、等しい角から等しい辺を導くルールを実装する。
3. 固定された頂点名に依存する既存ルールを一般化する。
4. 型付きカタログと実行エンジンを接続し、ルールの前提・結論・証明理由が一元管理されるようにする。
5. 図の見た目だけで条件を推測せず、点の順序・円の識別・角の位置などの明示情報を検証する。
