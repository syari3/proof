# 座標による図形条件チェック（初期段階）

## 目的

図形描画と図形成立チェックで同じ座標データを使えるようにし、与えられた座標配置が問題の条件に矛盾していないかを機械的に検査する。geometry-realization-checker.js は、座標を探索するソルバーではなく、**与えられた座標の候補（witness）を検査する検証器**である。

## 入力

- 問題データ: 既存の proof-problem version 1。
- 座標候補: { points: { A: { x: 0, y: 0 }, ... } }。
- 許容誤差: 任意の正の options.tolerance。既定値は 1e-7。

座標は有限な数値である必要がある。長さや外積の判定では、座標のスケールを考慮した相対許容誤差を使う。

## 現在チェックする範囲

- 直線を定義する点が同じ座標に潰れていないこと。
- 交点として宣言された点が両方の直線上にあり、直線の方向ベクトルが平行でないこと。
- 円周上の点として列挙された点が、同じ中心から同じ半径にあること。
- 線分長、点の順序（between）、平行、半直線の向き、弦に対する同じ側／反対側の条件。
- 指定した角の内部に点があること（ray-inside-angle）。
- 同位角・錯角について、角の頂点・辺が指定された横切る直線／2直線上にあること、2直線の平行性、角度の一致を座標から検査する。
- 動点について、円周上・選択弧の内部にあること、および動的条件 BA=BG などの線分長条件。
- 相似目標に含まれる三角形が座標上で退化していないこと。

## 結果の読み方

- coordinate-witness-invalid: 対応済みの条件に違反が見つかった。
- coordinate-witness-partial: 対応済み条件は通ったが、未対応条件が残っている。
- coordinate-witness-consistent: 実装済みの検査対象をすべて通過した。

valid: true は、**この座標候補が実装済みチェックに違反しなかった**という意味だけである。条件のすべてが検査済みであることや、座標候補が存在することの一般的証明を意味しない。未対応の条件や曖昧な弧選択は pending に残す。角の関係は数値座標と明示された直線・点の対応を照合するもので、一般配置に対する定理証明ではない。

## 出題・描画への接続方針

1. 構造検証で参照先とデータ形状を検査する。
2. 座標ソルバーまたは作図手順で候補座標を生成する。
3. この検証器で候補を反例検査し、未対応条件を明示する。
4. 証明エンジンで推論の妥当性を別に検査する。
5. 全条件の検証が完了し、退化や曖昧な交点がなく、証明も成功した場合だけ出題ゲートに通す。

数値座標の候補を1つ見つけたことは、その候補の条件整合性を示すが、問題文の条件が意図するすべての配置で定理が成立することの証明にはならない。特に入試証明では、座標図を見て正しそうに見えることを証明の代わりにしてはいけない。

## 次の課題

- 角・弧の向きと、円周上の点の巡回順序をより明示的に表現するデータモデル。
- すべての交点条件と、交点・弧の端点を含む点の順序を網羅的に検査すること。
- 動点条件をパラメータ化して、指定範囲内に解が存在するかを調べる処理。
- 数値探索の結果と、記号的／厳密な保証を区別するステータス。
- 描画コードと検証コードが同じ作図定義を利用する仕組み。
